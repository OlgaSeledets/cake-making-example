# Крошка — лендинг кондитерской

Готовый демонстрационный сайт для портфолио. HTML + CSS + TypeScript, без UI-фреймворков. Vite используется только для разработки и сборки. Сервер и API для работы опубликованного сайта не нужны.

## Самый простой способ опубликовать на GitHub Pages

1. Распакуйте ZIP на компьютере.
2. Создайте публичный репозиторий на GitHub, например `kroshka-cakes`.
3. Загрузите **содержимое** распакованного архива в корень репозитория. `index.html` и `assets/` должны лежать прямо в корне, а не внутри дополнительной папки. ZIP целиком загружать не нужно. Для публикации достаточно `index.html`, `assets/` и `.nojekyll`; остальные файлы нужны для редактирования и документации.
4. Откройте **Settings → Pages → Build and deployment**.
5. Выберите **Source: Deploy from a branch**, ветку **main**, папку **/(root)**, нажмите **Save**.
6. Дождитесь завершения публикации. Ссылка появится в Settings → Pages: `https://ВАШ-ЛОГИН.github.io/kroshka-cakes/`.

Для этого способа Node.js и команды сборки не нужны. Все пути в готовой версии относительные: сайт работает как в корне домена, так и в подпапке репозитория. На GitHub Pages публичный сайт доступен всем.

## Что внутри

```text
index.html             Готовая страница
assets/                Собранные CSS, JS, фотографии и локальные шрифты
.nojekyll              Отключение обработки Jekyll
source/                Исходники проекта и автоматические тесты
.github/workflows/     Необязательная публикация через GitHub Actions
licenses/              Лицензии шрифтов
CREDITS.md             Источники фотографий и шрифтов
CHECKS.md              Проверки и ограничения
LICENSE                MIT для кода
```

## Разработка

Нужен Node.js 22.12+ (рекомендуется 22 LTS), npm.

```bash
cd source
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite. Прямое открытие `index.html` через `file://` не предназначено для ES-модулей; используйте локальный сервер или GitHub Pages.

```bash
npm run build       # TypeScript strict + production-сборка в source/dist
npm test            # Логика, DOM-взаимодействия, ARIA-связи и axe
npm run preview     # Локальный просмотр собранной версии
```

После изменения исходников для публикации из ветки скопируйте содержимое `source/dist/` в корень репозитория с заменой `index.html` и `assets/`, затем отправьте изменения на GitHub. Не копируйте `node_modules/`.

### Автоматическая сборка через GitHub Actions

В архиве уже есть `.github/workflows/pages.yml`. Он использует `source/`, выполняет `npm ci`, сборку и тесты, затем публикует только `source/dist/`.

1. Загрузите весь проект, включая скрытую папку `.github/`.
2. В **Settings → Pages → Source** выберите **GitHub Actions** вместо публикации из ветки.
3. Откройте **Actions → Deploy to GitHub Pages → Run workflow**.
4. Дальнейшие изменения в `source/` на ветке `main` запускают публикацию автоматически.

Выберите один способ публикации. При загрузке через веб-интерфейс GitHub убедитесь, что скрытые файлы и папка `.github/` тоже добавлены. Если они не добавились, простой способ из ветки продолжит работать.

## Что можно нажать

- Навигация и мобильное меню, закрываемое по Escape и выбору ссылки.
- Фильтры каталога с объявлением числа результатов.
- Карточки открывают подробности торта в нативном `<dialog>`.
- Кнопка в карточке подставляет десерт в калькулятор.
- Три вкуса: вкладки, стрелки, циклическое переключение без автопрокрутки.
- Расчёт по весу / количеству капкейков и варианту оформления.
- Проверка минимального срока: 3 дня от текущей локальной даты посетителя.
- Модальное окно с деталями расчёта и скачивание UTF-8 TXT.
- FAQ на нативных `<details>` и `<summary>`.
- Модалка с информацией о демопроекте.

## Доступность и адаптив

- `lang="ru"`, один H1, landmarks, последовательные заголовки и ссылка пропуска навигации.
- Нативные кнопки, ссылки, поля, `dialog`, `fieldset`/`legend`, `details`.
- `aria-expanded`, `aria-controls`, `aria-pressed`, `aria-selected`, `aria-labelledby`, `aria-describedby`, live-уведомления и текстовое значение диапазона.
- Вкладки: ← / →, Home / End; один tab stop. Модалки: нативное удержание фокуса, Escape, возврат фокуса после закрытия; фон недоступен при `showModal()`.
- Явный `:focus-visible`, альтернативные описания фотографий, скрытие декоративных элементов от screen reader.
- `prefers-reduced-motion`, forced colors, отсутствие автопереключения и мигания.
- CSS-состояния для телефонов от 320 px, планшетов и широких экранов; fluid grid, переносы, мобильное меню, отсутствие фиксированной ширины форм.

Это не сертификат WCAG. Реальный браузер и скринридер в среде подготовки были недоступны; перед использованием в коммерческом проекте пройдите ручной список в CHECKS.md.

## Где редактировать

- Тексты, секции, метаданные: `source/index.html`.
- Цвета и типографика: переменные в начале `source/src/style.css`.
- Цены, минимальный вес, описания десертов: `source/src/pricing.ts`. При изменении цен обновите также карточки в HTML и начальные значения формы.
- Поведение: `source/src/main.ts`.
- Фотографии и шрифты: `source/public/assets/`.

Кондитерская вымышлена. Фотографии используются как иллюстрации; сайт обозначен как портфолио-проект, без фиктивных отзывов, адресов, телефонов и обещаний реальной отправки.

Форма **не отправляет заказ** и не принимает оплату. Она рассчитывает стоимость и скачивает файл локально. Персональные контакты не запрашиваются, серверного хранения, внешних шрифтов, аналитики и cookies нет. Для реального бизнеса подключите выбранный обработчик формы и замените демонстрационные условия, сведения о компании и документы на реальные.
